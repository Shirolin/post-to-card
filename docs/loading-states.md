# 预览加载态：每一条的做与不做

> **状态：五条都已定，四条已落地。** 首帧的 1:1 闪现、图片格子的空洞、占位块的等待信号、
> 排除推文时的列表重排，都改完了（`App.tsx` / `Card.tsx` / `modal.css` / `card.css`，
> 理由写在各自的注释里）。没动的是主题回读与导出等待，理由见逐条。

## 决定规则

按顺序用；上一条能解决，就不进下一条。

1. **先量第一帧。** 「感觉生硬」要落成一个数值：哪一帧、什么属性、从多少到多少。没量过的
   过渡是在给猜测配动画。
2. **能消掉就不加过渡。** 跳变的成因几乎都是「先猜一个值，再改成真值」；把猜的那一帧藏起来，
   比给跳变包一层更短、更稳，也不掉帧。
3. **只过渡合成层属性**（`opacity`、`transform`）。`zoom`、`height`、`aspect-ratio` 是布局属性，
   过渡等于每帧 reflow，长卡片上直接掉帧。
4. **被光栅化的元素不承载预览态。** 导出是克隆 DOM 再光栅化：`<img>` 上的 `opacity`/`class`
   一旦表示「预览里已加载」，克隆里那句话说谎就是一个看不见的图片。预览态放在容器上，
   装饰节点挂 `data-html2canvas-ignore`。
5. **打开时只有一段节拍。** 卡片跟着 dialog 的入场走，不再叠第二段独立动画。
6. **失败不假装在加载。** 装饰性动效只在「确实在等」时出现；`prefers-reduced-motion` 的
   全局降级在 `modal.css` 末尾，新动效自动继承它。
7. **容器变了尺寸，就是内容位移的一部分。** 卡片按高度重新适配时，只动内容一定会看到
   「内容在动、整张卡在跳」；两层必须同一时长、同一曲线地一起动，否则不如都不动。

## 清单

| 加载态 | 改前用户看到什么 | 处置 |
|---|---|---|
| 首帧的 `fit` | 卡片按 640px 画一次，再缩到适配比例 | 测量完成前不画，之后淡入 |
| 图片 | 空盒子，照片一张张「顶」进来 | 模糊的小图先淡入，小图到达前扫一道高光，落定后整层淡出；失败时停下并露出缺图标记 |
| 排除/恢复推文 | 卡片瞬间缩短/变长，后面的帖子瞬移 | 位置 FLIP + 卡片比例 FLIP，同节拍；2→1 只动卡片，1→2 只让回来的那条淡入 |
| 主题（存储回读） | 可能是默认主题闪一下 | 不动，见逐条 |
| 导出等待 | 按钮 spinner + 状态行（已有） | 不动 |

## 逐条

### 首帧的 `fit`：藏起来，不加过渡

**量到的**：1200px 宽的 harness（`?modal=1&grid=4`）里逐帧采 `.preview-scale` 的 `style.zoom`，
先是 `"1"`，一次测量之后变成 `"0.81"`。窗口越窄跳得越大。

**处置**：测量完成前卡片不画（`opacity: 0`），量完加 `.is-measured` 淡入 0.18s。单向标志：
之后换主题、换画幅、换推文都会移动几何，但那是用户的编辑，卡片必须一直在。

**为什么不给 `zoom` 加过渡**：见规则 3；而且那会把「先猜错再改对」变成一段看得见的变形。

**为什么不直接量完再挂载卡片**：卡片在 `App` 的同一棵树里，节点存在才能被 `ResizeObserver`
量；先挂再藏，比拆成两棵树简单。

### 图片：模糊的小图先到，落定后淡出

**处置**：每个图片格在图片之上铺一层 `--quote-bg` 的凹色块。凹色块里先放图片自己的小图
（`getPhotoPreviewUrl` 把 `name=orig` 换成 `name=small`），小图到了就以模糊态淡入；拿不到小图
的源（非 X 图、data URL）只留色块和一道扫光。`load` 之后容器加 `is-picture-loaded`，整层淡出
0.24s，模糊的替身换成清晰的原图。

**为什么不再放图片图标**：一个图片符号压在灰块上，读作「缺图」，正是加载态最不能像的东西。
真实的小图模糊着出现，说的是「这张照片正在对焦」，比任何图标都准确。

**为什么不是整块明暗呼吸**：这个主题的对比度下（浅纸上的浅凹色），整块 `opacity` 1 → 0.55
就是同一块浅灰亮一点、暗一点，截图里和「格子空着」分不出来。

**扫光只是小图到达之前的过渡**：它动的是伪元素的 `transform`（合成层），在小图到达
（`is-preview-ready`）、小图自己失败（`is-preview-failed`）、原图到达（`is-picture-loaded`）或
链失败（`is-picture-missing`）时停。扫光与淡出在同一层：一个动伪元素的 `transform`，一个动块
自己的 `opacity`，不抢属性——旧版因为整块 `opacity` 呼吸才不得不拆成内外两层。

**小图失败不等于图片失败。** 小图是这张图的第二个请求，它 404 时原图可能还在路上，所以格子
留在等待态（色块、缺图标记都不出现），只是扫光停下——没有东西可以再宣布了，继续扫就是规则 6
说的「假装在加载」。旧版没有 `onError`，这一路会让扫光一直扫到原图落地。

**扫光的颜色是相对凹色加一档明度，不混进别的颜色。** 十二个主题的凹色深浅不一：按 `--surface`
或白色混出来的亮部，在深色主题里偏暗（看起来是凹色自身在闪）、在浅色主题里几乎看不见，在
Brutalist 上方向还相反。改为 `oklch(from var(--quote-bg) calc(l + 0.1) c h)`——固定加一档感知
明度、保留色相与彩度，于是每个主题的亮部都是「同一块材料被照亮」。色域钳制后仍比凹色亮的主题
（Brutalist）只有约 1.04:1，记作材料上限。`color-mix(…, #ffffff 30%)` 是给不认相对颜色的浏览器
的退路。

**模糊半径跟着格子宽度走**：`3cqw`（占位块自己是一层 `container-type: inline-size`）。固定 px
在大图上太清、在四宫格缩略图上糊成一团；按宽度的比例，两种尺寸读起来一样。

**为什么不给 `<img>` 自己加淡入**：见规则 4。被画进 PNG 的那个 `<img>` 的不透明度不能是预览
状态的函数。小图是另一个节点，且整层挂在 `data-html2canvas-ignore` 下，导出不会带上。

**为什么用 `--quote-bg`**：卡片里已经有「比纸面低一层」的语义（引用块），空图片格是同一个
东西，不再造一个 token。

**失败是另一种样子**：链走空时扫光停下、模糊替身隐藏（否则会一直显示一张不会来的图），中央
露出 55% 的带斜杠标记。标记常驻树里，显隐由 `is-picture-missing` 决定，因为它是命令式写上的、
不会重渲染。

**代价**：每张图多一次小图请求；这是模糊替身的成本。失败时格子留在色块上，破图不会露出来，
只多一个缺图标记——导出的降级路径同样用一个色块占位（`FALLBACK_PLACEHOLDER_DATA_URL`），
两处对「缺图」是同一类表达；只是预览取主题的凹色，导出取固定灰。

**导出不预热替身**：导出先从光栅化的克隆里摘掉全部 `data-html2canvas-ignore` 节点，替身的小图
因此不会被 proxy 再取一遍，也不会被算进 `failedImageCount`；`prepareCardImages` 同样跳过它们，
并且只沿卡片内部找标记——卡片外面那层预览壳也带着这个属性，向上找过头会把整张卡判成忽略。

**导出换源不算「图片到了」。** 导出前会把卡片里的远程图临时换成 data URL（画布同源规则），
失败图换成灰色占位——那也是个能 load 的 data URL。所以换源期间给 `<img>` 打上
`EXPORT_SWAP_ATTR`，卡片的 `load`/`error` 处理器跳过它；否则一次导出会把失败格永久标成
「已加载」（色块消失、破图露出），还会把占位图 100×100 记成这张图自己的比例——`recordShape`
只记一次，之后真图到了也不会再改。

### 排除/恢复推文：两层 FLIP

这一步有两个位移同时发生，缺一层就会互相打架：

1. **帖子本身。** 卡片是一列帖子，删掉一条会让下面每条瞬间上移。动手前把每条的 `offsetTop`
   记下来（`offsetTop` 而不是 `getBoundingClientRect`：后者带着预览的 `zoom`），渲染后把差
   写成 `translateY`，再过渡回 0。谁算「新加入」由前后两次 `threadSession` 的帖子集合决定，
   不由「有没有量到旧位置」决定——单帖卡片量不到任何帖子，恢复一条时会把原来就在屏上的那条
   也当成新的，闪一下。
2. **卡片自己的比例。** `fit` 是卡片高度的函数，帖子少一条，整张图的比例也会变（headless
   1200×900 下实测同一张卡：`zoom` 0.357 → 0.520）。这一层用 `transform: scale(旧/新)` 回放，因为
   `zoom` 是布局属性（规则 3）；`transform-origin: 50% 0` 对应舞台上「顶边不动、水平居中」的缩放。
   用户显式选出来的形状不回放：缩放按钮明说「现在 100%」，画幅控件明说「这张卡现在是 16:9」，
   两者都是命令而不是后果，下一帧就该是新形状（`handleConfigChange` 记下这一次跳过回放）。

**1↔2 的边界只动卡片。** 帖子数是 1 时卡片换成单帖布局，没有位置可量、也没有位置可移，
所以 2→1 只有卡片比例在动，1→2 只有「回来的那条」淡入、原本那条不动。这是布局换了，不是帖子
挪了，硬套 FLIP 只会让单帖内容从错误的位置滑进来。

**帖子按 id 加 `key`。** 不加的话 Preact 按槽位复用 DOM：排除一条后，后一帖的内容会被画进前
一帖的节点里，而节点上的「图片已到」「链已失败」这些标记是命令式写上的，会跟着节点留给一张
已经不在那里的图片。探针里给每条帖子打了节点标记，断言留下来的那条用的是自己的 DOM。

**为什么要裁剪。** 帖子被 `translateY` 放回旧位置时，卡片**已经**变短了，未裁剪的帖子会画到
纸面之外、悬在舞台上。所以列表在动画期间临时 `overflow: hidden`，帖子是「从卡片底边滑进来」
的，动画结束再放开。

**为什么不做「被删的那条先淡出」。** 那会把卡片的最终尺寸推迟 150–200ms，而导出尺寸、二维码
这些读的都是它；现在被删的那条直接消失，剩下的滑动与裁剪已经把「它曾经在那儿」讲清楚了。

### 主题：不动

存储回读在挂载后立即完成，其时刻落在 dialog 那 200ms 入场动画的起始段（不透明度接近 0）。
**这一条没有量到可见证据**，所以不提前等存储、也不给卡片加淡入——等存储会推迟「点击即开」，
而那是这个功能唯一不能牺牲的东西。

如果以后去掉 dialog 的入场动画，这条要重新考虑：那时首帧会露出来，做法应是把「有存储值」
之前的那一帧也藏掉，而不是给主题加过渡。

### 导出等待：不动

按钮 spinner、`exporting` 文案、`role="status"` 的实时播报都在。图片预热的进度条可以做，
但那是给 4 并发 fetch 造第二套状态机，收益是几十毫秒的观感——不做。

## 没有引动画库

（业界叫什么名字不重要，落在这里就是：**这段动效不足以付一个运行时的价**。）

理由三条，都具体到这个项目：

- **工作量**：需要的是几段 `transition`、一个 `@keyframes`、两次 FLIP。最小可用的一档（Motion
  One 的 mini animate，约 2–3KB gzip）换不来什么；再往上（Framer Motion / Motion 全量、GSAP）
  是几十 KB，而这个 content script 是手写构建、体积受控的。
- **导出管线**：库通过内联 `transform`/`opacity` 编排，被克隆进光栅化的正是这些属性。规则 4
  的约束是库不会替你想的。
- **宿主环境**：Shadow DOM + X 自己的 SPA + 内容脚本，库的 SSR/事件绑定假设大半用不上。

**什么时候重新评估**：需要真正的时间线编排（多元素串行、交错）、手势驱动的动画，或者弹簧物理。
且只能落在预览外壳上，不能落在 `#post-to-card-export-target` 的子树里。

**View Transitions 用不上。** 列表重排本是它最合适的场景，但它在 Shadow DOM 里要整页快照，
而宿主是 X 的 SPA：转场期间页面滚动不可控，且被快照的是整个文档而不是这张卡。手写 FLIP 只
需要一次前后测量，已经够用。

## 探针

`node dev/verify-motion.mjs` 就是这条探针：它起 vite 与 Chrome，把真实的 `App`/`Card` 挂进
`dev/probe-motion.html`，做三次手势（3→2、2→1、1→2）、一次换画幅（3:4→16:9）与一段图片等待，
逐帧采样后**断言**：帖子与卡片各层是否真的在飞、边界处是否只有卡片在动、换画幅时卡片内还有没有
布局属性在过渡、占位块的高光是否在扫、失败后是否停下且露出缺图标记、淡出有没有中间帧、导出换源
会不会被当成「图片到了」。改这两个动效的一侧时跑它，别靠截图。

读什么：`.preview-scale` 的 `style.zoom` 与 `getComputedStyle().transform`、
`[data-tweet-id]` 的 `offsetTop`、计算后的 `transform` 与 `opacity`、
`#post-to-card-export-target` 的 `offsetHeight`、`.media-grid` 的 `margin-top`、
`.media-item` 的 `max-height`、占位块 `::after` 的 `transform` 与缺图标记的 `opacity`。

换画幅那条的红落在 **`margin-top` 与图片高度上限逐帧变化**，不是卡片高度逐帧变化：实测旧规则下
上限虽然过渡了，但图片盒子自带比例，限制根本没生效，卡片高度只动了 3px。要让它为「高度在动」而红，
得有一条真正改变卡片高度的布局过渡——这条断言防的是那个形状，不是这一次的两行。

探针里的照片是本地地址，派生不出 X 的小图变体，所以模糊替身本身不在它的断言里（用真实 X 图在
harness 里看）；派生规则由 `tests/tiers/tier1_features.test.ts` 的 F11.3b 锁住。

**一条断言的完成判据是"会红"，不是"现在全绿"。** 写或改断言时先让被修的东西坏掉（把守卫改成
`if (false)`、去掉 `key`、把 `playFrom` 写成直接写终值），确认那条断言真的失败，再恢复。这一步
是这轮补出来的：两条看起来在检查"没有位移"和"没记住替身的形状"的断言，去掉了对应的修复也照样
通过——一条读的是动画结束后的内联样式，另一条读的是无论如何都会被覆盖的比例。

四个会让探针说谎的坑，都是这轮踩到的：

1. **浏览器面板的页面不跑渲染帧。** 不只是嵌 iframe：直接打开的页面里 `requestAnimationFrame`
   也不推进、CSS 过渡停在起点值、`ResizeObserver` 的回调不投递——量出来像是「样式没生效」和
   「比例没重算」。所以探针必须用真浏览器跑（`verify-motion.mjs` 用仓库既有的零依赖 CDP 驱动）。
2. **这台机器开着「减少动态效果」。** 在它下面每个时长都被 `modal.css` 末尾那条全局规则压成
   0.01ms，于是脉冲是直线、FLIP 一帧结束、淡出是硬切。CDP 里先
   `Emulation.setEmulatedMedia({ features: [{ name: 'prefers-reduced-motion', value: 'no-preference' }] })`
   再导航；否则量到的是降级行为（脚本把这条也当成一条断言）。
3. **harness 的照片是内联 SVG。** 解码是瞬间的，占位块在任何截图里都已经淡出。要审「还没到」
   的样子，得让图片真的不回来，或者慢得回来：指向一个不回答的地址（脚本自己起了一个）比指向
   404 更合适——404 会走完失败链，占位块正确地停下扫光，正好看不到等待态。
4. **`?modal=1` 是 light DOM**（`.ptc-scope`），探针选择器不能只在 `post-to-card-container`
   的 shadow root 里找。

脚本默认 **headless**：headless 也绘制（`new` 模式跑完整的渲染管线），而 headed 的窗口一旦被
别的窗口盖住，Chrome 可能停止给它帧——那是「动画没跑」的假红。要看着它跑就设 `PTC_HEADED=1`。

## 实测

以下都在 headless Chrome（1200×900 窗口）里量，`prefers-reduced-motion` 模拟为
`no-preference`。

| 场景 | 改前 | 改后 |
|---|---|---|
| 首帧 `fit` | `zoom` 从 `1` 跳到适配值 | 测量前 `opacity: 0`，量完 0.18s 淡入 |
| 占位块等待 | 静色块 | 小图到达前：高光从 `translateX(-100%)` 扫到 `100%`，1.4s 循环 |
| 小图到达 | 无 | 模糊的小图 0.32s 淡入，扫光停下 |
| 一条链失败 | 和等待时一样是一块静止的灰 | 扫光停下、模糊图隐藏，换上 55% 的带斜杠标记 |
| 图片落定 | 无过渡 | `opacity` 1.00 → 0.80 → 0.43 → 0.01 → 0，0.24s |
| 导出换源（失败图） | 一次导出后格子的色块永久消失、破图露出 | 换源期间不写「已到」，恢复后仍在等待 |
| 排除一条帖（3 → 2） | 帖子瞬移 500px；`zoom` 0.357 → 0.520 一跳 | 帖子被位移 500px 后过渡归零；卡比例 0.687 → 0.88 → 0.96 → 0.98（中间帧）→ 1；列表在动画期间 `overflow: hidden` |

## 已知不做

- **给 `zoom`、`height`、`aspect-ratio` 加过渡。** 见规则 3。卡片的比例变化是用 `transform`
  回放的，不是把 `zoom` 做成动画。
- **在导出路径上加任何过渡。** 光栅化拍的是克隆的一次快照，动画只可能拍成中间态。
- **被排除的那条帖子单独淡出。** 见「排除/恢复推文」末段。
- **主题首帧的额外处理。** 见「主题：不动」。
